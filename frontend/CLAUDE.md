### Web app (`frontend/`)

**The top bar** (`components/nav/TopBar.vue`, in `App.vue`, 2026-10-13) is on every page and never scrolls away: Home, Back and the theme toggle, 44px tall (`--topbar-h`; the dev ribbon, the review's sticky status bar and `scroll-padding-top` start below it). Home goes to `/chat` (since 2026-11-18; `HOME` in `lib/nav.ts`). Back goes where the page on screen says (`useBack` in `lib/nav.ts`), because the overview, a section's start screen and an open review are states of one page, not addresses in the browser's history: from a start screen, an open review or a run view it goes to that report's list of sections (as the masthead's back link did, which is removed); from the overview it goes Home; on `/` it is disabled, not hidden. So Back never leaves the app, and a page opened from a link in a new tab still has one. While something typed on the weekly analyst inputs form is not saved, Home and Back ask first (`useLeaveGuard`). Since 2026-10-19 the bar also carries the wordmark "Cytonn Weekly" (text and a dot; the project has no logo) over the rail, as wide as the rail.

**The shell and the side rail** (2026-10-19; `components/nav/AppShell.vue`, `SideRail.vue`, `lib/shell.ts`). Every route except `/` (the start page stands alone) is drawn inside `AppShell`: the dev-mode ribbon directly under the top bar, then the rail on the left and the screen beside it. The page still scrolls as a whole (the top bar, the ribbon and the rail stick; there is no inner scroller). **The ribbon is the shell's**: it is in the page's flow and sticky under the top bar, and each screen says whether it shows with `useShellRibbon(label)` (only the screen knows whether what it holds was drafted by the local model); no screen draws a ribbon or pads for one any more. The rail shows the report and week and the mode (from `/api/config`) and a collapsible group "Sections" with one item per section of the report on screen, each with its state, plus (off the overview, where the tally already says it) "n of N sections approved" with a thin bar and, for the weekly, when export unlocks. **State is never colour alone**: each state has its own icon, a tooltip and the item's `aria-label` ("<section>, <state>[, why it does nothing]"): approved, rejected, in review, not drafted, not available yet, being drafted, and "state not known" (a dashed circle). **The sticky element is the rail's wrapper, not the `<nav>` inside it** (a sticky element cannot leave its parent's box, and the parent is only as tall as the nav; a test scrolls the page and checks the rail has not moved). Widths: from 768px a full rail (224px) on every load; below 1366px a button (or Escape) folds it to a strip of icons (56px, no sideways scroll) for that visit only, and nothing is stored, so it is full again on the next load; under 768px it is a drawer over the page that the top bar's Menu button opens (the state is in `shell.menu`, not stored). Its landmark is named "Report sections" and must never contain "app": the tests find the top bar by `getByRole("navigation", { name: "App" })`, which matches by substring. Texts in the rail must not equal strings the tests match page-wide (for example "Fixed Income: Not drafted" or "drafting now"), and it uses no `role="status"` or `"alert"`.

- **The rail's data is the overview's payload and nothing else** (`lib/shell.ts`, `createShell(load)`; the app's instance reads with `api.getOverview`). A page that has just read the overview hands it over (`setOverview`), so on the overview the rail and the cards are built from the same object, and states are derived with the cards' own `stateOf`. **A state is shown only while it is known to be current.** `invalidate()` makes every state unknown at once and drops any read already in flight; it is called when a page mounts that does not itself supply a payload (the overview page, the run view, the not-found page), after an approval or a rejection (`ReviewScreen` watches the review's `decision`), and a failed read leaves the states unknown. A response that arrives after a newer one is dropped. The sections stay listed while their states are unknown. Nothing is cached across those events, defaulted or guessed. The run view reads the report again when the run is known and when it ends; the start screen's own 5-second poll hands over each payload.
- **Going anywhere from the rail asks first when something typed is unsaved** (`mayLeave()`, the same guard as Home and Back; see `lib/nav.ts`: the analyst form arms it with `useLeaveGuard` while any field, pasted table or grid holds an unsaved edit, and "Discard changes" lifts it). The Focus topic has no guard, as before. A section item opens only where the overview page is on screen (`useShellActions`: the page registers `goToSection` and `home`, and removes them when it goes away): on the run view and the not-found page the sections are inactive, as is the one already on screen and an unavailable one (`aria-disabled`, and the name says why). `goToSection` reads the report's sections afresh and goes where that section's card button goes (its review when it has a current one, else its start screen); it never trusts what the rail was showing.
- **Tests:** `frontend/src/lib/shell.test.ts` (7: no state before a read, states and the approved count from the payload, drafting and unavailable, an update after a rejection, a failed read, out-of-order reads, a companion's kind) and `e2e/tests/rail.spec.ts` T59 to T65 and T69 (the five sections, the three widths, the ribbon and that the rail sticks while the page scrolls, opening a section from the rail, the leave guard, the run view, a rejection, an approval, and the neutral mark when the sections cannot be read).

**Side panels and the rule about warnings** (2026-10-19; `components/nav/PageGrid.vue`, `PageAside.vue`). Four screens have a side panel and one layout: a content column (the feed) and, from 1100px wide, a panel on its right (a quarter of the window, 20 to 28rem), below that the panel follows the feed (or comes first with `asideFirst`). The column is a container, so what is in it lays out by its own width. **The rule: no warning, notice, error, flag, dev-mode mark or button a person must press may live in a panel that can be folded away.** Everything of that kind is in the feed. Only the overview's "Report status" panel can be folded (it holds the tally and the export button; a panel folds only when `PageGrid` is given a `storageKey`; it is open on every load and a fold is not remembered), and the export's dev-mode notice shows the rule at work: the export bar is in the foldable panel, its notice is in the feed (T70). The other three never fold, and each says why: the start screen's "Inputs and steps" holds the uploads and their warnings (a file dated outside the week, a refused upload, a missing input), is first in the page's order and does not stick because it is tall (T71); the review's "Review items" is the work and holds the flags, and does not stick (T72); the run view's "This run" holds read-only facts (section, report, started, finished or stopped) and sticks; its status line, notices, failure and ways back are in the feed (T73 to T75). A new panel that holds anything to read or act on gets no `storageKey`. The chart card follows the rule: its notices are in the draft's column and its checks are items in the Review items panel.

**When an action fails with a named problem** (2026-10-23; `lib/attention.ts`, `components/AttentionDialog.vue`). An API error can carry `problems` (`backend/api/problems.py`: code, headline, target). `api.ts` tells the handler `main.ts` installs (`attention.raise`) about a failed **write** that names problems; a read never does, so polling and page loads never open a dialog. `PLACEMENT` gives each of the 38 codes one of three placements: `dialog` (the whole action failed: one alert dialog with the headline, "The details are shown on the page.", "Show me" and "Close"; a second problem replaces the first), `inline` (no dialog: the page goes to the sentence already shown beside what was clicked) or `none` (`review_not_found`, `run_unknown`: the page is itself the message). Going to a problem (`goTo`): after two frames, scroll its first `[data-problem]` into view only if it is out of view (at once under reduced motion), then focus it; never out of a field being typed in. The places are the six elements with `data-attention` (`review-status-bar`, `start-draft`, `week-picker`, `inputs-panel`, `analyst-form`, `export-bar`); "Show me" is not offered when the place has no box (a folded panel). Close and Escape return focus where it was, or to the problem when that element lost focus (the Draft button disables itself while it works). The full sentence is shown once, on the page; the dialog never repeats it. A Vitest (`attention.test.ts`) reads `backend/api/problems.py` and fails when its codes or targets differ from the frontend's. **The highlight (step 4, 2026-10-23):** the `[data-problem]` the page goes to (inline, or after Show me) gets `data-attention-on` (`highlight` in `lib/attention.ts`): a 2px outline in `--attention` (`#B42318` light, `#F27F73` dark; at least 5.5:1 on card, page, muted fill and flag tint, pinned in `contrast.test.ts`) beside the notice's own icon and text, and one 900ms background pulse, none under reduced motion. It goes with the notice (its `v-if`). **The export error is in the overview's feed**, not in the foldable Report status panel: `ExportBar` emits it and `OverviewScreen` shows it under the dev-mode notices inside its own `data-attention="export-bar"`, so Show me is offered with the panel folded (`canShow` unchanged). **First focus** in the dialog is Show me when it is offered, else Close (`onOpenAutoFocus`, a frame after opening, once the page has drawn the problem). Tests: T87 to T98 (`e2e/tests/attention.spec.ts`, failures stood in for with `page.route`). Not yet: the ribbon wrap.

**The chat page** (2026-11-17, Phase 8 checkpoint 4; `pages/ChatPage.vue`, `lib/chat.ts`, `chatApi` in `lib/api.ts`). `/chat?section=<slug>&period=Week ending YYYY-MM-DD`, inside the shell, laid out by `PageGrid`: a chat column and an aside "This conversation" (read-only facts: section, week, model calls and tokens used; never foldable). With no `section` it is a picker: the week (a select over the weeks `GET /api/previous/weekly` lists, defaulting to its latest Friday), "Whole report" (opens the first available section in the issue's order, because each section is its own conversation and there is no whole-report job) and one button per section. The sections come from the weekly overview payload, which is also handed to the rail (`shell.setOverview`), so the rail's items open chat sections here and Overview goes back. A section opens its conversation with `POST /api/jobs`, then the page reads `GET /api/jobs/{id}/messages?after=` and **polls only while the job is `working`** (`shouldPoll`); an idle or paused job is not polled. Failed polls wait longer each time and stop after five, saying to reload. A response that arrives after another conversation was opened is dropped. Replies are plain text (`whitespace-pre-wrap`, no `v-html`, no links, no markdown). A tool turn shows as "Looked at: <tool name>" only. A 409 or 429 shows the API's own sentence in an alert and the page reads the job again; a stop at a budget shows the state in words with an icon, the "Raise the budget" button (only for `call_budget` and `token_budget`; it is in the feed, not the aside) and keeps the box off until it is used. Saved cards are the two the code posts (readiness, review summary), drawn by `components/chat/ReadinessCard.vue` and `ReviewSummaryCard.vue`; the live cards below them are checkpoint 5. Every API answer is checked whole (`parseJob`, `parseMessage`, `parseListing`) and refused if it is not the expected shape. Tests: `frontend/src/lib/chat.test.ts` (parsing, merge, polling stop rules, status words, the conversation's polling with a hand-run scheduler) and `e2e/tests/chat.spec.ts` T116 to T119 (run by name: `playwright test chat`, which also runs `chatcards`; the test backend is in local mode, so T117 and T118 stand in for the job routes, the readiness route and the Bedrock config with `page.route`).

**Previous reports and the default week** (2026-11-03; `pages/PreviousReportsPage.vue`, `lib/previous.ts`, `GET /api/previous/weekly`, `weekly/export.approved_weeks`). ### Visual design system (`frontend/src/styles.css`)

The identity (restyled 2026-10-22 to Cytonn's own look, green, white and black; the pale navy workbench of 2026-10-19 and the warm "proof desk" before it are gone) is a pale grey page, near-white cards with hairline borders, black ink and a white top bar. It blends two design skills: **`ant`** for data-dense enterprise discipline and **`stitch`** for clean, high-contrast ink. Don't use `design-taste-frontend` for this screen; it is scoped away from dashboards and data tables. The layout borrows the pattern of a three-column home screen (a rail, one feed, a side panel) and nothing else from the product it was taken from: no name, logo, icon, wording or asset. The rules, all encoded as tokens in `styles.css`:

- **Type scale** (2026-10-23) 14/16/17/20/24/32 only (`--text-xs` … `--text-2xl`); nothing sets a size outside it. **14px is the floor**: helpers, source lines, chips, eyebrows and table headers are `text-xs` (14); the body, review item text, table cells, buttons and inputs are `text-sm` (16, inputs at every width, no `md:` step down); narrative paragraphs `text-base` (17 on a 28px line); the state glyph 13px; the Notable chart's labels 14px (`CHAR_W` 8.4 in `lib/notable.ts`). The chrome (rail, top bar, status bar) uses the same tokens. In the review items, an explanation that two or more not-auto-verified items share (the claims' "Not yet automatically checked..." note) is shown once under the group header (`ItemsPane.vue`), and those cards keep their "Not auto-verified" chip but leave the sentence out. **Arial** (`Arial, Helvetica, sans-serif`, a system face, nothing downloaded) for text and for the figures in tables and the review items, in tabular numerals; JetBrains Mono (`@fontsource-variable`, imported in `styles.css`) only for run ids, dates, file names, workbook cell references and the dev ribbon. The `word-spacing` correction Plus Jakarta Sans needed is deleted (Arial's space is wide enough). `@fontsource-variable/plus-jakarta-sans` is still in `package.json`, unused; removing it needs a lockfile change and was left.
- **Spacing** 4/8/12/16/24/32 (Tailwind steps 1/2/3/4/6/8). **Radii** (2026-11-13, the dense workspace): 4px chips and small boxes, 6px controls, 8px containers, full round for pills. Dark cards are flat (no shadow). From 1100px a page's side panel is a full-height rail (`PageAside`), and everything placed in it lies flat, divided by hairlines (`.rail-stack` in `styles.css`, unlayered so it beats the parts' own utilities). Standing cautions (dev mode, the export watermark, missing charts) use `Notice quiet`: a coloured edge and icon on the card fill, still `role="alert"`.
- **Colour** (2026-10-22). Brand green `#49B315` (`--primary`) is **for actions only**: primary buttons with black text (7.74:1), selection, a thin accent (the top bar's dot, the roman-numeral badges). It is 2.71:1 on white, so it is never text, a focus ring, a control edge, a progress fill or a review state on a light surface; there the darker green **`#2C7409`** is used (`--link`, `--ring`, progress fills; 5.77 on a card, 5.24 on the page, 5.11 on the green tint). Dark theme: `#49B315` is link and ring (6.67 on a card). Page `#F3F3F3`, card `#FEFEFE`, border `#E6E6E6` (decorative only), body grey `#44474E`, top bar `--band` white (black in dark). **A control's edge (`--input`) is at least 3:1 against every surface it sits on in both themes** (light `#767676`: 4.50 on a card, 4.09 on the page, 3.88 on the muted fill; dark `#8A8A8A`: 5.24, 5.59, 4.16). The only state colours are the three review states: `flag` (red `#B42318`), `warn` (amber, not auto-verified) and **`ok` teal `#006B5B`** (dark `#3FBFA8`), chosen so a clean item or an Approved chip can never be read as the brand green (about 170 degrees of hue against about 100). The dark neutrals (2026-11-13, a cooler near-black after the proposed dashboard designs) `#0B0D10` page and top bar, `#13161B` card, `#1C2027` muted fill, `#242932` border, `#7D8590` control edge, `#EAEAEA` ink, `#9AA1AB` muted text, the tints `#E8F4E0` and `#13240D`, and the light muted fill `#EDEDED` are derived, not Cytonn's. Figures are never coloured. **`frontend/src/lib/contrast.test.ts` reads the tokens out of `styles.css` and asserts 24 pairs in each theme (48 tests, plus 2 on the brand green): text pairs at 4.5, edges and rings at 3, state text on its 10% tint; change a token and re-run `npm test`.** The measured numbers are in the comment above the tokens.
- **States are shown by shape as well as colour** (`.state-flagged`: solid heavy bar + tint + "!"; not auto-verified: dashed outline + "?"; `.state-clean`: hairline + check glyph). The shapes did not change with the 2026-10-22 colours.
- **Not done yet (stages 2 and 3 of the restyle):** the rail is still light (a black rail with a green active item is planned) and warnings still use the one `Notice` box; no pop-up or toast exists. Brand green is never a status: the card's progress ring and number badge, the roman-numeral badges, the progress bars, the current-step marker and the rail's "in review" and "being drafted" icons are ink or grey. A disabled primary button is a grey fill (`--muted`) with a `--muted-foreground` label (7.95:1 light, 6.25:1 dark) and a not-allowed cursor.
- **Light, dark and system themes** (2026-10-13). The top bar's toggle has three states; the first visit follows the device (`prefers-color-scheme`). The choice lives in `<html data-theme>` (absent means System; `frontend/src/lib/theme.ts`), is remembered in browser storage with every read and write in try/catch, and is restored by an inline script in the `<head>` (`src/lib/theme-script.ts`) before the first paint, so a reload does not flash. Every colour token holds both values as `light-dark(light, dark)` and follows `color-scheme`; the `dark:` variant matches the chosen theme too. No component holds a colour of its own: the dev-mode stripe's colours are tokens (`--dev-*`), the same in both themes.
