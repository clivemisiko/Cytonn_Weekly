# Analyst chat agent notes

Phase 8 of the structural plan: a chat with a read-only agent, one conversation per report, period and section (`jobs.py`, tables `report_jobs` and `job_messages`). Built in checkpoints; this folder holds what exists so far.

- **`loop.py`, `answer()`**: answers the analyst's latest message, which the caller has already saved. Each pass is one model call (`BedrockAgent.converse` in `drafting/bedrock.py`, model from `CYTONN_CHAT_MODEL_ID`, else `BEDROCK_MODEL_ID`). Text ends the turn. Tool calls are checked, run, saved as `tool` rows and answered on the next pass. `jobs.begin()` takes the job so two workers cannot answer at once, and the job is never left `working`, even on a crash.
- **Limits**: tool calls per message (`CYTONN_JOB_MAX_TOOL_CALLS`) and the job's model-call and token budgets (`CYTONN_JOB_CALL_BUDGET`, `CYTONN_JOB_TOKEN_BUDGET`, counted in `report_jobs`). A limit saves a plain assistant message and the job as `paused` with a reason (`tool_calls`, `call_budget`, `token_budget`). A new analyst message resumes a tool-call pause. A budget pause stays until `jobs.raise_budget()` (the analyst's button) adds a fixed amount to that one job and logs a `budget_raised` run event.
- **`tools.py`**: a `Tool` has a Pydantic input model (extra fields refused), a `run` that only reads, and a `shape`. `execute()` checks the input, runs the tool and passes the result through `trim()`, which keeps only the keys the shape names and cuts strings and lists. A name that is not in the tool list runs nothing. **The agent never sees raw source text, workbook cells, notes or snip transcriptions: no tool's shape names them.** A tool's failure or refusal is a small `{"error": ...}` for the model to read.
- **Instructions hidden in data** are met three ways: free text reaches the model only as a short capped title or host; the system prompt says results are data; and the agent has no tool that changes anything, so the worst it can do is say something wrong. Cards and buttons are built in code, never from model text.
- **History**: `history()` rebuilds the Messages API turns from the saved rows (the last `HISTORY_ROWS`, cut back to a whole turn), so every `tool_use` has its `tool_result`. Cards are never sent to the model.
- **Run events**: every tool call emits `tool_called` through the observer given to `answer()`. The messages table is the durable record of calls; the events are the live feed.
- **Tests**: `backend/tests/agent_helpers.py` has `ScriptedBedrock` (a fake client that returns scripted replies and keeps the requests), so no test reaches a model.
- **Open for the API checkpoint**: a job left `working` by a crash or restart must be reset to idle at startup, as `interrupt_leftover_runs` does for runs.
