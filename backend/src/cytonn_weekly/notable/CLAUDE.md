### Notable this week (`notable/`, `/api/notable/{section}`, `frontend/.../NotablePanel.vue`; built 2026-10-14)

Suggestions that code works out from history (streaks, records, "lowest since", threshold crossings, expected ranges, pace), shown to the analyst with their working on the start screen and the review screen of each weekly section; the analyst accepts, edits or dismisses each. **A suggestion is a note to the analyst and nothing more: nothing it says is ever written into a draft, a figure, a review item, the analyst inputs form or the Word export,** and tests pin that. This task built only the panel, the shape of a suggestion, the place detectors plug in and the saving of decisions. **Nothing is registered and no history is read yet**: the detectors exist as a library of plain functions (see **Notable detector library**), but the real registry is empty, so the real app's panel says "Nothing notable has been computed for this section yet."

- **The shape, version 1** (`notable/suggestion.py`): `id` (16 characters of a hash of kind, section, week, series and window; wording and rank are not in it), `kind` (streak, record, since, trailing_compare, threshold_cross, expected_range, pace, drift), `section` (the slug), `week_ending` (YYYY-MM-DD), `headline` (one sentence built by code from a template, never by a model; at most 300 characters), `figures` (`{label, value, display, unit}`), `working` (`{series, rule, window, points: [{date, value, display}]}`, at least one point), `provenance` (`{kind: published | approved_review | analyst_workbook | typed | demo, label}`), `rank` (0 to 100), `version`. Constructing one with no headline, no working, no provenance, an unknown kind or a rank outside 0 to 100 raises `InvalidSuggestion`. Two provenance labels have one wording only: `analyst_workbook` reads "from the analyst workbook, not verified" and `demo` reads "invented demo item".
- **Where detectors plug in** (`notable/registry.py`): `REGISTRY`, a section slug to a list of detector functions, is **empty**. A detector takes a `DetectorContext` (the week only) and returns a list of `Suggestion`s; it is given no database, no file handle and no write access. `run_detectors` runs each one on its own: a detector that raises, or returns anything but a list of valid suggestions for its own section and week, counts as one check that could not run, none of its output is used, and the reason goes to the server log, never to the response. Duplicate ids are kept once; the result is ordered by rank, then id. The package imports nothing that drafts, checks, exports, fetches or calls a model, and a test reads its imports to keep it so.
- **Decisions** (`notable/store.py`; table `suggestion_decisions` in `schema.sql`, added with `CREATE TABLE IF NOT EXISTS`, so no existing table changed, which a fingerprint of their definitions pins): `(week_ending, section, suggestion_id)` is unique; `decision` is selected or dismissed; `edited_headline` only on a selected one; `dismiss_reason` only on a dismissed one (not_relevant, already_covered, figures_look_wrong, other, or none); `decided_at`. A new decision on the same suggestion replaces the old one and deleting the row restores it. Decisions are keyed by the id, so a suggestion whose series or window changes gets a new id and its old decision is left behind, unseen: detectors must keep an item's series and window stable from week to week.
- **API:** `GET /api/notable/{section}?week_ending=&report_type=` gives the suggestions, highest rank first, each with its `decision` or null, and `failed_checks`; the week must be a Friday (422), a section not in the weekly report is 404, and any other report type returns an empty list. `POST /api/notable/{section}/decisions?week_ending=` takes `{suggestion_id, decision, edited_headline?, dismiss_reason?}`: 404 for an id the section does not have that week, 422 for an empty or over-long edit, an edit on a dismissal or a reason on a selection; it answers with the whole list again, as the review routes do. `DELETE .../decisions/{suggestion_id}` takes a decision back (404 if there is none). `create_app(notable_registry=...)` is where detectors come from; left out it is the empty real registry. These routes have no authentication, as no route has.
- **The panel** (`NotablePanel.vue`, `NotableCard.vue`, the logic in `lib/notable.ts`): at the foot of a weekly section's start screen and of an open weekly review (its week is the period's Friday, else the section's `week_ending`, else a `week_end` that is a Friday; with none there is no panel). The top five open suggestions by rank, "Show all (n)" for the rest; each card has its kind, a provenance chip (with a warning glyph for invented and workbook-derived items), rank, headline, figures (each printed as `label = value`, because a label may hold a colon of its own: `figureLine`) and a "Show working" disclosure (rule, series, window, a line chart of the points, the points as a table). The chart (`WorkingChart.vue`, its geometry in `chartGeometry` in `lib/notable.ts`) is plain SVG drawn from `working.points` alone: a point's value places it and its display string is the only number printed (the lowest and highest at the left as the scale, the latest beside its larger filled dot; the oldest and latest dates under the ends); x is to scale by date so a gap looks like a gap; a flat series, and a single point, sit in the middle; token colours only, no animation. It is exactly as wide as its box (the unit-tested `chartGeometry` lays it out to fit, so it never scrolls and the 12px labels are never shrunk): with room (the line keeps at least 160px beside the labels) the scale is at the left and the latest label beside its dot; in a narrow box (a phone) the plot takes the whole width, the scale labels go above the top line and below the foot line, and the latest label goes above its dot (below it when the line arrives from above), always inside the box. Accept selects it. Edit rewords the headline; the original stays and is shown as "Original: ..." and saving an edit selects it. Dismiss takes an optional reason. "Selected for this week" is the worklist, with Edit, "Remove from list" and "Copy as text" (a read-only box if the clipboard is refused). "Dismissed (n)" lists the dismissed, each with Restore. The empty state, "One check could not run." and "could not be loaded" are quiet lines, and a failure in the panel leaves the rest of the screen working. A locked (approved or rejected) review's panel still works, because it never touches the review.
- **How only the demo instance has invented items:** `e2e/notable_demo.py` holds invented series (every name begins "Invented") that it runs through the real detector library, and `e2e/serve_e2e.py` passes the result to `create_app`. Nothing in `backend/` imports that file, no environment variable or data file switches it on, and the `demo` provenance exists in `backend/` only as the validator's fixed label (a test scans `backend/src` and `backend/api` for it). Every invented item carries the label "invented demo item", and the panel shows it on each card.
- **Tests:** `backend/tests/test_notable.py` (64: the shape and its refusals, detector isolation, selected, edited, dismissed and restored decisions, one row per suggestion, a restart, refusals, the new table beside the old, and that a decision changes no `coordinator_reviews` row, no analyst form file, nothing the export status reads and not the body of the real five-section `.docx`), `frontend/src/lib/notable.test.ts` (33), `e2e/tests/notable.spec.ts` (T47 to T58).

### Notable detector library (`notable/detectors/`; built 2026-10-15)

Seven detectors as plain functions over a series, in the notable shape (version 1). **Nothing here reads the database, a workbook, a file or the network, nothing calls a model, and nothing is registered in the real registry**; a later task feeds them from a history store and registers wrappers. A detector may only say what the points it was given support: it never extrapolates, never guesses and never repairs a series. Modules: `series.py` (the input), `wording.py` (every headline, rule and number format), `library.py` (the detectors; its docstring holds the rules and the rank formulas), `verify.py` (the independent check).

- **Input** (`series.py`): `Series(name, unit, points, provenance, decimals=None)`, points as (date, value) pairs, oldest first. Values come from strings, ints or Decimals, **never floats**. `SeriesError`, with the reason, for an unsorted or repeated date, a missing or non-finite value, a float, a bad date, a unit outside `pct, bps, multiple, kes_bn, kes_mn, usd_mn, index, count`, no points, a name containing a date (it would change the id every week) or a provenance that is not a `Provenance` (its kind and label follow the notable rules, so a workbook-derived series says "from the analyst workbook, not verified" and an invented one "invented demo item"). `decimals` overrides the unit's default (`wording.DEFAULT_DECIMALS`: pct 2, bps 1, multiple 1, kes and usd amounts 1, index 1, count 0).
- **Rules every detector shares:** *freshness*, nothing unless the latest point is dated `week_ending` (`pace` takes its cumulative figure's `as_of` date instead, see below); *minimum history*, each detector states one and returns nothing below it; *regularity*, a gap between neighbouring points above `max_gap_days` (default 10) ends the usable window for a run, a stretch, a mean or a range. Exact Decimal throughout; a derived figure is rounded half up to 6 decimals once and its display is rounded from that. Dates in a headline are written 2026-10-09.
- **The seven** (all keyword-only after the series; each also takes `section` and `week_ending`):
  - `streak(series, min_run=4)`: consecutive weekly rises or falls ending at the latest point; a tie or a gap ends the run. Rank `min(100, 40 + 10 x (run - min_run))`. **Its working also carries the point that ended the run** (the point just before the run's first point) as the oldest point, so the verifier can show the run is the longest: the rule says "The first point shown is the one before the run and is not part of it." and that point must be level with the run's first point, or move the other way into it, or lie more than `max_gap_days` earlier. When the run begins at the first point of the series nothing is added and the rule says "The run begins at the first point we hold, which is the first point shown; nothing earlier is held." (the verifier accepts that only when the rule says it). The figures, the headline, the window text (`current run`) and so the id are unchanged.
  - `since(series, min_points=26, min_stretch=12)`: highest or lowest "since DATE" (an equal value counts as at or beyond, so a tie ends the stretch), or, when nothing in the window is as extreme (kind `record`), "in the available history" / "a record ... in the history we hold" (the word record only with at least 52 weeks). **The record form says where its window starts**: "The window begins at the first point we hold." and the headline "(the earliest point we hold is DATE)"; when a gap cut the window the rule says "The window begins after a gap of more than N days; points before the gap are not looked at." and the headline is only "the {extreme} in the N weeks checked, since DATE", never "history". The record form also needs one point a week (the weeks counted equal the points shown); a window whose points are not one a week gets no record. The verifier accepts each wording only under the window sentence that allows it. Rank `min(100, 30 + weeks)`.
  - `trailing_compare(series, threshold, mode="pct", window_n=12, require_sigma=None)`: the latest against the mean of the previous `window_n` points (excluding it), as percent, absolute or basis points (percentage series only); `threshold` is the caller's, no default; the sample standard deviation count is shown with at least 8 previous points and a spread, and required only if `require_sigma` is set; a zero mean in percent mode gives nothing. Rank `min(100, 40 + floor(20 x (|difference| / threshold - 1)))`.
  - `threshold_cross(series, level, min_points=12)`: the previous point strictly on one side, the latest at or beyond `level` (equal counts as reaching it), consecutive weeks; says since when, or, when no point in the window was on that side, "for the first time in the N weeks we hold, since DATE" (N and DATE from the stretch actually checked; "history" is never used). When a gap kept earlier points out of the check the sentence says "in the N weeks checked, since DATE" instead, and the rule says which: "The window begins at the first point we hold." or "The window begins after a gap of more than N days; points before the gap are not looked at." (the verifier accepts "we hold" only under the first). The "since DATE" form carries no window sentence: it names the last time on that side and every point after it was checked. Rank `min(100, 40 + weeks)`.
  - `expected_range(series, window_n=26, slip_factor=5)`: strictly outside the lowest to highest of the previous `window_n` points, and, as a separate suggestion, at least `slip_factor` times or at most 1/`slip_factor` of their median (needs a median and a latest value above zero). Rank `50 + min(35, floor(10 x distance / width))`, 60 for a range with no width; slip 90.
  - `pace(cumulative, target, period_start, period_end, as_of, threshold_pp, min_elapsed_days=28)`: share of target against share of the period elapsed, **counted with `net_borrowing.Log.days`** (the reuse is real: `Log` is built from plain dates) over `(period_end - period_start).days`, so for the fiscal year pass `period_end = start + 364 days`; a straight-line projection, labelled as one. The cumulative series' latest point must be dated `as_of`, and `as_of` must be from `week_ending` to seven days after it (the value date after the Friday). Rank `min(100, 40 + floor(2 x |gap in points|))`.
  - `drift(name, price_now, price_previous, target, dividend_per_share, target_previous, dividend_per_share_previous, provenance)`: upside in both weeks (one division, exact), banded by **`equities.weekly.recommendation`, called, not copied**; fires only when the band changes **and the target and the dividend per share are the same in both weeks** (compared as numbers); if either moved it returns nothing (a move on price alone is the only kind built; a revised target is a different suggestion kind, not built). Both weeks' target and both weeks' dividend are in the figures (`Target now`, `Target a week earlier`, `Dividend per share now`, `Dividend per share a week earlier`) and the verifier checks each pair is equal before it accepts "target unchanged". Names the 0 to 0.1% zone "no band"; never says the target should change. Rank `min(100, 50 + 10 x steps)` on the order Sell, no band, Lighten, Hold, Accumulate, Buy.
- **A finding about the house band rule:** `recommendation` takes a float (the Universe of Coverage table calls it with `float(evaluate(...))`, and its tests use floats), and its thresholds are float literals, so a bare `Decimal("0.1")` gives no band at exactly 0.1%. The detector and the verifier convert at the call, as the table does. Where a displayed upside would round across a band edge (0.06% shown as 0.1%) the headline shows more decimals so that the number and the band never contradict.
- **Wording rules** (`wording.py`, every template listed in `TEMPLATES`, scanned by a test): no cause, prediction or advice; no "signal", "indicate", "trend", "should", "expect", "predict", "likely", "because", "recommend" and the like; at most 300 characters. Amounts read "Kshs 12.3 bn" and "USD 12.3 mn" as the report prints them (not "KES"). Series name and window text contain no date or latest value, so an id is the same week to week.
- **The self-check** (`verify.py`): each suggestion is verified before it is returned. The verifier reads the rule's parameters back out of `working.rule`, recomputes from `working.points` with its own code, and compares every figure value (to 6 decimals), every display (against its value at the decimals it shows), the figure list, the direction words and the whole headline. It imports nothing from the detectors (a test reads its imports) and keeps its own copy of each sentence, so a template changed on one side fails loudly. A mismatch raises `DetectorSelfCheckError`, which the registry reports as "one check could not run". **What it still cannot prove from the working alone:** that nothing is held before a window that says it "begins at the first point we hold" (a streak, a record, a first-time crossing). That is the detector's word; the rule states it, the verifier accepts the matching wording only when it is stated, and the golden tests and the seeded property loops check that the detector tells the truth (the window sentence agrees with whether anything is held before the working). The audit below lists what was found and closed.
- **Isolation** (`backend/tests/test_notable_detector_guards.py`): the package may import only the standard library (without anything that reaches a file, database, network or process), the notable shape, and `common.formatting`, `common.computed` (`show` and its formats), `equities.weekly.recommendation` and `fixed_income.net_borrowing.Log`, the last two imported inside the function that needs them because each pulls in a reader (about 1.3 s and 1.2 s to load). It opens no file and calls no `eval`. The scanner is itself tested on forbidden sources.
- **For the history-store and importer tasks:** a series' `name` is stable text and its `unit` fixed for good; **a change of unit mid-series is not detected** (the library and the verifier work on the numbers as given, so mixed units give wrong but self-consistent suggestions): start a new series, or store converted values. Points are weekly, the last dated the report Friday; a gap above 10 days silently shortens the window. Percentages are as printed (9.0, not 0.09). `pace` needs the period's start and end and an `as_of` date; `drift` needs the previous Friday's price and last week's target and dividend per share as well as this week's, and returns nothing when either differs.
- **Tests:** `backend/tests/test_notable_series.py` (72), `test_notable_detectors.py` (85 goldens, boundaries, ranks, stable ids, wording; one golden for each way a streak ends: a reversal, a tie, a gap and the start of the series; the probe that was "history we hold"; a record with a gap before it; drift when the target or dividend moved), `test_notable_verify.py` (178: every figure, display, point, rule parameter and headline word tampered; a pre-run point that continues the run refused; a first-time or record headline that claims more than its window, or the wrong window start, refused; weeks counted against points shown; a drift whose target or dividend changed refused even with every figure consistent; the detectors shown to call it; each case is built on its own, so one broken detector fails only its own tests), `test_notable_detector_guards.py` (38), `test_notable_detectors_property.py` (8: 500 seeded random cases per detector; `hypothesis` is not a dependency), with `tests/detector_helpers.py`.

**What each verifier can prove from a working alone (audited 2026-10-15; every gap found is closed):**

| Detector | Gap found | State |
| --- | --- | --- |
| `streak` | nothing proved the run was the longest: the point before it was not in the working | **fixed**: the working carries the point that ended the run (a tie, a move the other way, or a gap above `max_gap_days`); the verifier checks it fails to continue the run; the start-of-series wording is accepted only when the rule says it |
| `since` | the record form did not say where its window began; the verifier accepted either "the earliest point we hold" or "unbroken from" wording; the weeks counted were not tied to the points shown | **fixed**: the rule says where the window starts (at the first point held, or after a gap); each headline is accepted only under its sentence; a gap-cut window says "weeks checked", never "history"; the weeks counted must equal the points shown |
| `trailing_compare` | none: the working is the exact window and the claim is not a maximum | no gap |
| `threshold_cross` | "for the first time in the history we hold" was judged on the unbroken window only (three earlier points behind a 14-day gap still gave that headline) | **fixed**: "for the first time in the N weeks we hold, since DATE" with N and DATE from the stretch checked, "checked" instead of "we hold" when a gap cut the window, and the window sentence in the rule; the verifier refuses a headline that claims more than the working shows |
| `expected_range` | none: every point of the range is in the working | no gap |
| `pace` | none: every input is in the rule and the figures are recomputed | no gap |
| `drift` | "target unchanged" was the caller's assertion: the working held only the two prices | **fixed**: last week's target and dividend are inputs, both weeks' are in the figures, the detector fires only when both are unchanged, and the verifier checks they are equal before it accepts "target unchanged" |
