### Local model speed settings (development only)

Four opt-in environment variables shorten a local (Ollama) draft. They are read in one place, `read_local_settings()` in `drafting/local.py`, when a provider is created, and `LocalProvider` and `LocalNarrativeProvider` both use them. The Bedrock provider never reads them. Unset, empty or blank means the default, which is the behaviour before they existed (the requests are pinned by `backend/tests/fixtures/local_provider_requests_before.json`).

| Variable | Range | Default |
| --- | --- | --- |
| `CYTONN_LOCAL_MAX_SEARCH_RESULTS` | 1 to 5 | 5 |
| `CYTONN_LOCAL_RESULT_CHARS` | 500 to 3000 | no extra cut (Exa already returns at most 3000 characters per result) |
| `CYTONN_LOCAL_NUM_THREAD` | 1 to 16 | not sent (Ollama picks the thread count) |
| `CYTONN_LOCAL_NUM_PREDICT` | 1024 to 4096 | 2048 |

- **`num_ctx` is fixed at 8192 and has no variable** (4096 breaks drafts). `keep_alive` is not sent, as before. The `num_predict` minimum is 1024 because a cap of 700 truncates Markets Review briefs. A per-model override in `_MODEL_CONFIG` still wins over `CYTONN_LOCAL_NUM_PREDICT`.
- **An invalid value** (not an integer, or outside the range) logs one warning naming the variable and the range, and the default is used; it is never clamped.
- **Trimming happens after the search, where the prompt is built** (`_trim_results`), so the Exa request and `backend/data/exa_cache/` are the same whatever the settings. The draft is validated against the trimmed list, so a link or claim citing a result the model was not shown is dropped. A result's text is cut at a word boundary and never inside a number; its title and URL are untouched.
- Each provider logs its effective values once, at first use (logger `cytonn_weekly.drafting.local`): a WARNING when any setting is off its default, so it shows without any logging setup, and INFO when all four are defaults. Nothing of it enters a draft.
- `docker-compose.yml` forwards the four to the `api` service as `${NAME:-}`, so an unset one arrives empty and is read as unset. The fast preset is in `.env.example`.

### Drafting with Amazon Bedrock (`CYTONN_LLM_PROVIDER=bedrock`, 2026-11-05; `drafting/bedrock.py`)

The server drafts on Amazon Bedrock; the direct Anthropic provider (its `web_search` path) was removed on 2026-11-16. **Exa is the search service for two things: the local (Ollama, Phi-4 Mini) provider's own search, and, since 2026-11-06, the gather step that finds sources for a Bedrock draft (`common/gather.py`, see "The gather step" below). Bedrock itself is still given no search, fetch or agent tool and never sees a query or a key: code searches, code fetches, and the model is handed saved pages.** Bedrock's model is given no search, fetch or agent tool and holds no credentials (the code holds the AWS keys): **it writes only from sources that code hands it** (pages the analyst supplies with their URL and date, or pages fetched in code from any address the analyst gives, under the network safety rules below), never a web search by the model. **The gather step (2026-11-06; `common/gather.py`, `POST /api/sources/gather`, wired in `work_run` of `api/main.py`):** at the start of every run of a section that calls the provider, when `CYTONN_LLM_PROVIDER=bedrock`, each piece from `source_pieces.pieces_for` is searched for sources before the Bedrock call, so a draft no longer starts from an empty Sources panel. The Executive Summary has no pieces and stays out; the synchronous draft route (`POST /api/sections/{slug}/draft`) does not gather, only a run does. A piece that already has `CYTONN_SOURCES_ENOUGH` (3) saved sources is not searched. Otherwise `exa_search` (injected as `search_sources` on `create_app`, so tests never reach Exa) queries with the piece's label plus the market name (`CYTONN_SOURCES_MARKET`, default "Kenya"; a Digital Payments piece, `Piece.market` False, gets its label alone because its companies are global) and the piece's own window (`Piece.window`: a weekly piece's six days up to its Friday, a Markets Review piece's period or the draft's week for a company, `Piece.start`/`Piece.end`), through a results cache in `exa_cache/` (`gather_<hash>.json`, keyed by query, domains, window start and today; `CYTONN_EXA_REFRESH` ignores it). Pass 1 is restricted to the brief's `preferred_domains` (a company's IR domain for Digital Payments); pass 2 is limited to the other hosts the source policy allows for the piece (see **Source policy** below; none means no pass 2) and runs when pass 1 left fewer than `ENOUGH` usable pages or the piece has no domains. A result is usable with an address and a date inside the window; social media, duplicate addresses, addresses already saved for the piece and addresses in `dismissed.json` are dropped; the newest `CYTONN_SOURCES_MAX_PAGES` (4) are fetched with `fetch_page` (every safety rule unchanged; `origin="found"`, the off_list and insecure flags as for any fetch, the search's date as the date when the page states none). A page `fetch_page` cannot read is kept from the text Exa returned instead (at least `MIN_CHARS`), through `from_paste` with the flag "Text supplied by the search service" (`TEXT_FROM_SEARCH`), shown on the card and the review; with no text it is skipped. Limits: `CYTONN_SOURCES_MAX_QUERIES` (2 per piece), `CYTONN_SOURCES_MAX_PAGES` (4 per piece), `CYTONN_SOURCES_GATHER_SECONDS` (150 for the whole gather, up from 60 on 2026-11-12 for the weekly Equities companies, checked between searches and pages; one Exa call waits at most 20 s). Nothing in it can fail a draft: each piece and each page is wrapped, a failure logs a WARNING with the host and error class only, and counts are all it logs. With no `EXA_API_KEY` nothing is searched and the run says so once (`sources_search_unavailable`). The run events are `sources_looking` and `sources_found` (the count in `detail`) per searched piece. "Search for sources" (once "Look again") is `POST /api/sources/gather` for one piece: 409 while a draft that reads that piece is running or queued, once an hour per piece in memory (a draft's gather counts), except that the first look after any source of the piece is removed is not held back. Removing a source found automatically records it in `dismissed.json` in the Friday folder (by piece and address) so no later gather brings it back; removing a pasted or hand-fetched one does not. The model's prompt is capped per source (`SOURCE_CHARS`, 12,000 characters) but the number of sources per piece is not; a gather adds at most `MAX_PAGES` to a piece that had fewer than `ENOUGH`. `bedrock.py` imports neither the gather module nor any local provider module, and `sources_for` still reads saved sources only. The two Bedrock providers (`BedrockProvider` for Digital Payments, `BedrockNarrativeProvider` for every other section and the Focus outline, lead and conclusion) are independent of the local ones: the prompts, the JSON reply schema and the check that every link and claim cites a source the model was shown live in the neutral `drafting/prompts.py` and `drafting/replies.py`, which both the local and the Bedrock providers import (the local request bodies are unchanged and pinned by `tests/fixtures/local_provider_requests_before.json`). Everything downstream (claims, flags, the exact-match checker, review, export) is unchanged. **`CYTONN_LLM_PROVIDER` must be set (2026-11-16):** unset or blank is "not configured". `api.main.provider_problem()` then returns `NOT_CONFIGURED` (`drafting/factory.py`: names the variable and the two values `bedrock`, `local`; the value `anthropic` returns `ANTHROPIC_REMOVED`, a sentence saying it was removed and to set bedrock), so both draft routes and `POST /api/runs` answer 409 (`drafting_off`) before a seat is taken or anything is fetched or gathered, and `POST /api/snips/.../read` answers 409 too; both factories (`provider_name()`) raise a `ValueError` with the same sentence; `GET /api/config` reports `provider: "not configured"`, `provider_valid: false`, `spends_api_budget: false` and the sentence as `provider_problem`. The test suite's autouse fixture (`conftest.default_test_provider`) sets `bedrock`. Nothing selects Bedrock but the switch.

**Source policy (2026-11-16; `equities/source_policy.json`, read once by `common/source_policy.py`).** Which hosts may reach a draft, per section slug (and per piece where listed; a company piece of Equities reads its own site and hosts from `companies.json`): `named` hosts (official or company sites), `news` hosts (`figures_from_sources: false`: they may back highlights and prose, table figures come only from the readers) and a global `never_read` list (bloomberg.com, businessdailyafrica.com, nation.africa, nation.co.ke: the tool never fetches or searches them; the analyst types the value, pastes the text with its date, or sends a snip). `kind_for(section, piece, host)` answers "named", "news" or None. The gather step searches pass 2 only on the policy's other hosts for the piece and reads a found page only if the policy allows its host; `fetch_page` refuses a never_read host whoever asks but takes any other public host when an analyst adds it. Two flags, no new field on `SourceText`: "News site: ..." (`NEWS_SITE`, any news or never_read host) and "Added by analyst" (`ADDED_BY_ANALYST`, origin fetched or pasted), shown on the source card and the claim's review item. `bedrock_provider.by_policy` drops a saved source the policy does not allow for its piece unless it was added by hand (origin fetched, pasted or snip, or the flag; this also covers sources saved before the flags existed) and emits a `source_left_out` event naming it.

- **The sources (steps 2a to 2c, built 2026-11-06):** `bedrock_provider.sources_for(subject, week_end)` reads the saved sources for a piece from `common/sources.py` and nothing else: no search, no fetch, no network call on the Bedrock path. A source is a `SourceText` (id, subject, week_end, url, host, title, published_date, fetched_at in UTC, origin `fetched` or `pasted`, text, sha256 of the raw bytes or the pasted text, chars, flags) kept under `<data dir>/inputs/sources/<Friday>/` as `<id>.txt`, the raw bytes beside it for a fetched page (`.html` or `.pdf`) and one `manifest.json`; the id is the first 8 hex characters of a hash of subject, url and content, so the same source twice is one; every read checks both hashes and a changed file is refused with a plain sentence (`SourceError`, a `ValueError`, so a draft shows it as it stands). A piece is filed under the Friday on or before the end of its window, and its subject is matched ignoring case and spacing. **Getting a source:** `fetch_page(url, subject, week_end, http_get=...)` takes http or https from any host (2026-11-06; it no longer needs a site on a list), on port 80 or 443 only, and refuses: another scheme, a username or password in the address, social media, a redirect to another host, a host (a typed IP address, or any address its name resolves to) that is private, loopback, link-local (169.254.169.254 included), unspecified, reserved or multicast, IPv4 or IPv6, checked on the first request and again on every redirect, an oversize page, a reply that is neither HTML nor a PDF, a 404, an empty, login or paywall page and one too short to be an article, each with its own sentence; it reads HTML with `html.parser` and PDFs with pdfplumber, and takes the date from the page's meta tags or `time` element when plainly there, else leaves it empty. TLS verification is httpx's default and there is no switch to turn it off; a certificate failure gives its own sentence (the site's certificate could not be verified; paste the text, or try the http version if the site serves one). **Odd replies (2026-11-12):** header names are read in any case, and a missing one is "unknown", not an error: no `Content-Length` leaves the body's own length to count against the 5 MB cap (`http_get_once` once raised a `KeyError` there, which `fetch_page` reported as a network error), and no `Content-Type` is judged by the body (a PDF, or text that starts like HTML, is read; anything else is refused as "no type stated"). A redirect with no `Location`, a timeout, a 429 and a 3xx that is not a redirect each have their own sentence, an empty body is "no readable text", and only a real connection error (`http.NETWORK_ERRORS`) reads "a network error". Any other exception reads "replied in a way the tool could not read. Paste its text instead" and the log line holds only the host, the exception class and the innermost project frame (`sources._inner_frame`), never the message, the address's query, headers or page text; a refused status is logged with its number. The address is resolved once before the request, so a DNS answer that changes in between (rebinding) is not caught; a note in `fetch_page` says so. `from_paste(url, date, text, ...)` needs the URL and the date, refuses social media, keeps the text exactly as given, and gives the same `off_list` flag as a fetch (`list_flags(host)`). **Two flags on a source:** `off_list` ("host not on the approved list", the existing marker, for a fetched or pasted source whose host is not a known site) and `insecure` ("Not secure: the page could have been altered in transit", a page fetched over http://, judged on the final address after redirects). The source card in the Sources panel and the claim's review item show them in words. **The known-sites list is one constant, `common/sources.APPROVED_SITES`, now only a label** (29 hosts: the briefs' `preferred_domains` plus Real Estate's `PREFERRED_SITES`; a test checks it covers every brief domain), and `SOCIAL_DOMAINS` beside it. **The reply and the check:** the prompt holds the numbered saved texts (at most `SOURCE_CHARS`, 12,000 characters each; the check reads the whole saved text) and the forced `submit_draft` reply returns a headline, a paragraph and claims, each with `text`, `quote` and `source_id`. `review/checks.check_sourced_claim` keeps a claim only if its source is one that was supplied, its quote is in that source's saved text word for word after normalising whitespace, non-breaking spaces, quote marks and dashes (no case folding, no fuzzy match), and every number in the claim is in the quote (`figures_in`). A failed claim is dropped with a warning naming the reason; a piece with no surviving claim is unavailable. The verified quote becomes the claim's `cited_text`, so `check_claim` and the review work unchanged, and the claim's review item carries `source_id`, `sha256`, `fetched_at`, `host`, `published_date`, `origin` and `source_flags`. With no source saved, a piece is `no_story` with "No sources were supplied for this piece, so nothing was drafted. Supply the pages to read." and no Bedrock call is made. **The date window at draft time (2026-11-16):** `sources_for` still returns every saved source of the piece, but both Bedrock providers pass what it returns through `bedrock_provider.within_window(results, label, start, end)`, with the `start` and `end` the draft gives the provider (`draft_pieces(window=...)`: the weekly sections and the companies part pass the report week's six days up to the Friday, a Markets Review passes the period, every other caller the six days up to its `today`; Digital Payments' `_week_window(today)`). A source dated outside it is not shown to the model: it is a draft warning ("<piece>: the source "<title>" from <host>, dated <date>, is outside this draft's dates (<start> to <end>), so the model was not shown it. ...") and a `source_left_out` run event (label the title, detail the host, date and window; skipped line in the run view). A source with an empty date, or one that does not read as an ISO date, is kept and its result carries the flag "No date on this source" (`sources.NO_DATE_FLAG`, shown with the claim's source flags; the saved source is not changed). A snip's date defaults to the report Friday (`real_estate/snips.confirm`), so it counts as dated. **A confirmed snip (origin `snip`) skips the window altogether (2026-11-17):** it is the analyst's own choice, so it is shown to the model whatever its date, and when the analyst typed a date the source carries the flag "Date typed by the analyst: <date>" (`sources.TYPED_DATE`, set through `from_snip(..., typed_date=True)` by `snips.confirm` and the PDF confirm; none when the date defaulted to the Friday); a fetched or pasted page keeps the window. **`NarrativeBrief.dated_only`** (2026-11-17): a brief with it set leaves out a source with no date, with a draft warning and a `source_left_out` event, instead of keeping it with "No date on this source"; only the three weekly Fixed Income briefs set it, and they also carry the prompt line `fixed_income.weekly.IN_THE_WEEK` (the event itself must have happened in the report week; a recap of an earlier decision does not qualify). With every source left out the piece is `no_story` as with none, and the warnings say why. Tests: `test_sources_in_window.py`. **Routes** (no protection, as every `/api` route): `GET /api/sources?section=&report_type=&period=&sections=` (each piece of the section with its sources and the known sites, under the key `approved_sites`), `POST /api/sources` (a url alone is fetched; with a date or text it is pasted), `GET /api/sources/{id}/text` (plain text), `DELETE /api/sources/{id}`; plain `HTTPException` sentences, and a change is refused (409) while a draft holds the slot. `create_app(..., sources_root=None, fetch_source=source_store.fetch_page)` is how tests keep it off the network and in a temp folder. **Which pieces a section has** is read by `source_pieces.pieces_for(report_type, period, slug, sections=(), today=None)` from the same briefs and company list the builders use: weekly Fixed Income, Equities and Real Estate their brief labels, Digital Payments its five companies, Focus its typed titles (not a closing "Recommendations and Conclusion" part), and each Markets Review section its briefs (Digital Payments adds "Other notable digital payments sector highlights"); The Executive Summary has none. **Focus with Bedrock needs typed section titles**: with none the draft is refused before it starts (409 `draft_sections_required`), because there is nothing to search for a proposal. **The last look (2026-11-06):** every gather records, per piece, `{looked_at, found, searched}` in `looks.json` in the Friday folder (`sources.record_look`, written by `gather_piece`, and with `searched: false` by `gather()` when no search service is set up or its key is refused; a piece that already has enough sources is not looked at and records nothing), and `GET /api/sources` and the other source routes return it as `gather` (null before any look); only a time and two counts are kept, never a key or search text. **The panel is calm until a search has really found nothing:** a piece with no sources and no look says "Sources are found automatically when you draft." with a "Search for sources" button under its title (`lib/sources.pieceState`); while it searches the card says "Looking for sources…"; only `gather.searched` with `found` 0 and no source gives the amber "Nothing found yet for this piece..." notice; `searched: false` gives a neutral note. The start screen's confirmation before a draft names only pieces in that last state (`piecesNothingFoundFor`) and is skipped when there are none. **The screen:** with the Bedrock provider each section's start screen has a "Sources" panel (`SourcesPanel.vue`, `SourcePieceCard.vue`, helpers in `lib/sources.ts`) and the review shows each claim's source host, date, verified quote, saved-copy fingerprint and a link to the saved text, and marks a host off the list, or an http page, in words. Tests: `test_sources.py`, `test_sourced_claims.py`, `test_sources_api.py`, `test_source_pieces.py`, `frontend/src/lib/sources.test.ts` and `e2e/tests/sources.spec.ts` (T107 to T114; run with `E2E_VARIANT=bedrock`, see `e2e/serve_e2e.py`; written, not yet run).

- **Many users at once (2026-11-06):** drafts run concurrently up to `CYTONN_DRAFT_CONCURRENCY` seats and queue beyond that (see **Drafting seats and the queue** in backend/api/CLAUDE.md); the retry and the shared cool-off above are what keep concurrent drafts from all hitting Bedrock's throttle together. The api stays one process.
- **Variables (names only; `.env.example` lists them):** `BEDROCK_MODEL_ID` (default `us.anthropic.claude-sonnet-4-6`, an inference profile; recorded as `drafted_by: "bedrock:<model>"`, so it is **not** a dev draft: only `local:` is), `AWS_REGION` or `AWS_DEFAULT_REGION`, then either `AWS_ACCESS_KEY_ID` + `AWS_SECRET_ACCESS_KEY` (+ `AWS_SESSION_TOKEN` for temporary keys) or `AWS_BEARER_TOKEN_BEDROCK`. `EXA_API_KEY` is read by the gather step only (the Bedrock module never reads it), together with `CYTONN_SOURCES_ENOUGH`, `CYTONN_SOURCES_MAX_QUERIES`, `CYTONN_SOURCES_MAX_PAGES` and `CYTONN_SOURCES_GATHER_SECONDS`; both compose files pass these by name only. `CYTONN_LLM_MODEL` is the Anthropic path's and is not read. `CYTONN_LOCAL_*` (Ollama speed settings) are ignored.
- **Client:** the SDK's `anthropic.AnthropicBedrock` (anthropic 1.9.0, `anthropic[bedrock]` in `pyproject.toml`, which adds `boto3` and `botocore`). It posts to `/model/<id>/invoke`, so an inference profile ID works. The bearer token is read by the client itself and wins when both it and keys are set; keys are signed with SigV4 by boto3's chain, so boto3 is needed only for keys. A host role or profile is not looked for by the pre-check (it reads the environment only).
- **The call:** the reply is requested as a forced client-side function call (`submit_draft`) so it arrives as JSON; no server tool and no `pause_turn` continuation. `max_tokens` is 4096 unless a brief carries its own (Focus: 6000 a section and the conclusion, 600 the lead, 300 the outline) and the outlook's 800; a reply cut off at the limit is discarded as invalid JSON. **Retries (2026-11-06; `_Chat._create`):** the SDK client is created with `max_retries=0` so retries never stack; a call answered 429 or `ThrottlingException`, 503 or `ModelNotReadyException` is made again up to `CYTONN_BEDROCK_RETRIES` calls in all (default 5), waiting `CYTONN_BEDROCK_RETRY_BASE_SECONDS` (default 2) doubled each time, at most 60 s, with jitter; `AccessDenied`, `Validation`, expired credentials and `ServiceQuotaExceeded` are never retried and keep their sentences, a call that returned is never made again, and a retry is not a new entry in `self.requests`. Each wait is one `retrying` run event (the provider reaches the run's observer through `run_events.current_observer`, set by the worker thread). After any throttle every new Bedrock call from any draft first waits 5 s (`_cool_until`, one per process). The sleep is injectable (`sleep=`).
- **The spend record and the call cap (2026-11-16).** Each `_Chat` keeps its own `usage` (calls, input tokens, output tokens, and `unreported` for a reply that stated no counts); `bedrock_provider.track_usage()` is a context manager (a contextvar, like `current_observer`) that sums every instance created in the draft's thread, and `build_tracked` in `api/main.py` wraps the section's build in it on `POST /api/runs`, `POST /api/sections/{slug}/draft` and `POST /api/reviews/draft`. A draft that made at least one Bedrock call saves `section["usage"] = {model, calls, input_tokens, output_tokens[, calls_without_token_counts]}` with its content (tokens and calls only, no money; a draft with no Bedrock call has no `usage`; the model is the configured `BEDROCK_MODEL_ID`). `CYTONN_BEDROCK_MAX_CALLS_PER_DRAFT` (default 60, a whole number of 1 or more, a bad value logs one warning and uses 60) caps the calls of the whole draft (the tracker's count; with no tracker, the instance's): the call after the limit makes no request and raises `BedrockError` (`CALL_LIMIT`: "This draft reached its limit of N Amazon Bedrock calls (...), so no further call was made and nothing was saved from it."). **A provider error does not keep finished pieces:** `draft_pieces` and the builders let `BedrockError` propagate (a throttle, access denied and the cap alike), so the run is `run_failed` and nothing is saved; only a cut-off reply is kept as a `no_story` piece. A retry of one call is not a second call. Not covered by the tracker: snip and PDF reads (`read_snip`, `read_pdf_passages`, their own routes; each is capped per instance). Largest section by code (not measured on a live draft): the weekly Equities, up to 3 highlight briefs plus 15 company pieces, 18 calls; Focus with 8 typed titles, 9; Digital Payments, 6; weekly Real Estate, 6. Tests: `test_bedrock_usage.py`.
- **Before a draft starts** (`provider_problem()`, the 409 pattern): a plain sentence when the region or the AWS credentials are missing or blank, or when keys are used and boto3 is not installed (a missing `EXA_API_KEY` is a 409 for the local provider only, and `env.key_override_warnings()` checks `EXA_API_KEY` only when the provider is local). At start, one warning names which AWS variables are set and which are not, never a value.
- **Failures** (`problem_for`): `AccessDeniedException`, `ValidationException`, `ThrottlingException`, `ServiceQuotaExceededException`, an expired or refused credential, a server-side error and a network error each give one fixed sentence (`BedrockError`, shown as it stands by `failure_message`), with no library text and "drafting again will not help" only where that is true.
- **Differences from the removed Anthropic path:** the model returns a quote with each claim instead of a cited span, and code checks the quote against the saved page (see the sources bullet above); a claim whose quote and figures pass is still `not_auto_verified`, because its wording is never verified; each piece carries "Written by Amazon Bedrock (<model>) from the supplied sources."; citation verification (6b) is as limited as for the local provider.
- **The server needs a force-recreate after any `.env` edit:** `env_file` is read when the container is created, so `docker compose up -d --force-recreate api`; a restart is not enough. `docker-compose.server.yml` needs no AWS lines, because the api inherits `docker-compose.yml`'s `env_file`.
- **Which setting wins, and the log lines:** only `BEDROCK_MODEL_ID` chooses the model on this path (`CYTONN_LLM_MODEL` is ignored, and the startup line says so when it is set). The startup line prints the model actually used and where it came from; each request then logs one WARNING line (so it shows with no logging set up) with its number, the model, the input and output token counts and the stop reason, counts only. The Docker image installs with `pip install -e .` from `pyproject.toml`, which lists `anthropic[bedrock]` and so `boto3`; there is no `backend/uv.lock` in the repository (checked 2026-11-17 with `git ls-files`), so `pyproject.toml` is the only list of dependencies.
- **Testing on the droplet:** `deploy/bedrock-droplet-test.md` is the runbook: the `.env` names, `./deploy.sh`, the force-recreate, the startup line to expect, an ordered smoke test that drafts one weekly Real Estate piece (Affordable housing) from three supplied sources, the failure sentences, the rollback and how to read the request and token counts.
- **Tests:** `backend/tests/test_bedrock_provider.py` (fakes only: a fake Bedrock client, `sources_for` replaced by a fake page, and the real SDK client against a mock transport; it also pins that the module imports no local provider, mentions no Exa and subclasses neither local provider, that no sources means no call, and the usage log line). No live Bedrock call has been made. Written 2026-11-06 and not yet run.
