# scripts/

Manual, run-by-hand scripts against live services: diagnostics, plus the summary-email entrypoint. None runs automatically. Run each from `backend/` after `pip install -e .`.

| Script | What it does | Cost | When to run it |
| --- | --- | --- | --- |
| `check_digital_payments_live.py` | Fetches the 7 Digital Payments stock rows from Yahoo Finance and prints price, prior close, Year Open (the first trading day's close), w/w %, YTD %, forward EPS and forward P/E with their source dates. Fetch only: no drafting, no checking. | Free | After touching `digital_payments/fetcher.py`, or to compare the P/E column against Yahoo's quote pages. |
| `check_digital_payments_highlights_live.py` | Runs the real highlights drafter, the table fetch and the outlook drafter, then prints the composed section (headlines, bodies, links, cited claims, warnings). | Needs `CYTONN_LLM_PROVIDER` set; spends model budget with `bedrock`; free with `CYTONN_LLM_PROVIDER=local` (Ollama + Exa, dev only, not for publication) | To eyeball a real draft, or to check citation spans after changing `highlights.py` or a provider. |
| `send_weekly_summary.py` | Previews, and with `--yes` sends, the latest approved Word summary of a section (default `digital_payments`, the only one with a summary today) to `CYTONN_SUMMARY_RECIPIENTS`. Prints section, run, approval status, `drafted_by`, recipients and SMTP host first. Refuses (non-zero exit, nothing sent) for a missing/undecided/rejected review, missing SMTP config, or any `local:` (dev-mode) draft. | Sends **real email** with `--yes` once SMTP is configured | Once a week, after the analyst approves the section and before publish. |
| `import_history.py` | Reads the history sheets of the equities workbook and the fixed income mastersheet (by sheet name and label or date) into the history store. **A dry run unless `--apply`**: it prints per series the rows seen, the points, their date range and why rows were set aside, plus how many are new or already stored, and never a value. `--db FILE` uses a scratch SQLite file instead of the configured database. Existing points are never touched, so a re-run adds only what is new. On the server: `docker compose exec api python scripts/import_history.py /app/data/inputs/weekly/<Friday>/equities_workbook.xlsx /app/data/inputs/weekly/<Friday>/fi_workbook.xlsx` (dry run), then the same with `--apply` once the counts are approved. | Free; `--apply` writes to the configured database | Once, to load the history; again only if a workbook gains history the store lacks. |
| `replay_history.py` | Replays the stored history against the equities workbook's own cells. Needs a scratch SQLite file (`--db`, required: it never uses the configured database and never reads `.env`); `--fill [OTHER.xlsx ...]` first imports the equities workbook and any others into that file. For every week it works out, with `CYTONN_HISTORY_READS=on` forced, what the builders would read from the store (the running totals' before, the foreign weeks, the total the year before closed on, last Friday's prices, the market P/E's average over the workbook's own AVERAGE window) and compares it with the workbook's cells by exact match. Prints week, series, PASS or FAIL or SKIP and the size of any difference, never a value; failures and skips by default, every line with `--all`; exits 1 on any FAIL. A running total that is not exactly its running sum passes when it is within 0.06 (the team's hand edits) and fails beyond; a new year's restart is a SKIP. The fund table is not replayed (the workbooks hold only the latest week's). | Free; writes only the scratch file | After a new import, and before switching `CYTONN_HISTORY_READS` to `on`. |
| `check_exa_ir_sourcing.py` | Queries Exa for each of the 5 highlight companies, IR domain first and general web as fallback, and prints what comes back. No LLM involved. Temporary diagnostic, not a dependency of the drafter. | Exa API only (`EXA_API_KEY`) | To see whether a company's IR site has news this week before blaming the drafter. |

Keys and `CYTONN_LLM_PROVIDER` are read from the repo-root `.env`. The `PYTHONPATH=src` prefix shown in the scripts' docstrings is not needed once the package is installed with `pip install -e .`.

`seed_fund_list.py <mastersheet.xlsx> <out.txt>` writes the fund names of the mastersheet's 'Money Market Performance' table, one a line and names only, to a text file that is pasted into the fund list editor on the chat's fund table card (the list is then loaded on the server the same way). Run from `backend/`; keep the file out of the repository.
